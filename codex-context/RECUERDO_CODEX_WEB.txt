Fecha de actualizacion: 2026-04-17

OBJETIVO GENERAL
- Proyecto con ESP32-S3 para controlar cabezal y motores por CAN.
- La PC usa una app de Windows, no navegador.
- La app debe poder hablar con el ESP32-S3 por USB nativo o por WiFi.
- El USB nativo del ESP32-S3 no debe aparecer como COM para el cliente.
- El flasheo y debug se hacen por UART externo con CH340/FTDI.

DECISIONES TECNICAS YA TOMADAS
- App de PC en C# WinForms sobre .NET 8.
- Firmware en ESP-IDF v6.0.
- USB nativo del ESP32-S3 como dispositivo vendor-specific con WinUSB.
- Programacion y rescate por CH340/UART separado.
- WiFi como STA con hotspot/laptop o red del cliente.
- CAN a 1 Mbps.
- Dos buses CAN usando un solo TWAI del ESP32-S3, seleccionando CAN1 o CAN2 por software y remapeando pines.

PROBLEMA USB YA INVESTIGADO
- Sintoma observado:
  El primer comando por USB funciona.
  El ESP responde.
  El segundo comando falla y la app dice que no puede escribir o abrir el dispositivo.
- Con desconectar y reconectar USB, vuelve a funcionar una sola vez.

DIAGNOSTICO MAS PROBABLE
- El problema principal estaba del lado del firmware USB, no de la UI.
- El patron coincide con un endpoint OUT que no quedaba listo para recibir el siguiente paquete.
- Se corrigio el callback de TinyUSB para liberar el buffer RX despues de procesar un paquete.

ULTIMA CORRECCION IMPORTANTE EN FIRMWARE
- Archivo:
  C:\Users\Users\Desktop\acuratex final\control de motores\main\main.c
- En el callback:
  tud_vendor_rx_cb(...)
- Se agrego:
  tud_vendor_n_read_flush(APP_USB_VENDOR_ITF);
- Esta correccion se hizo porque TinyUSB vendor puede requerir flush del buffer RX para aceptar el siguiente paquete OUT del host.
- Despues de este cambio, el firmware fue recompilado correctamente.
